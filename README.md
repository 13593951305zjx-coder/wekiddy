# 音频识别与重要信息提取课程项目

项目提供本机网页版，包含音频转文字、大模型提取重要信息、人声音高统计图三个功能。默认通过 faster-whisper small 转写中文，使用 Ollama 的 qwen2.5:3b 提取摘要、关键词、事实、决定、待办和问题；librosa pYIN 分析音高。默认本地模式无需 API Key。

转写文字、分段文字及重点信息统一使用 OpenCC 转为简体中文，网页、历史记录和文字导出保持一致。繁简转换只处理字形，不会自动纠正语音识别中的错字。

“完整转写”按已识别的语音分段从上往下逐条显示，每条开头标注原始音视频的起止时间，例如 `[00:12.40–00:18.60]`；复制转写和导出 TXT 也保留这些时间段。已有带分段时间的历史记录可直接使用，未保存分段时间的旧记录仍保留原文。

点击每条转写的文字，或右侧播放图标，会在结果区的原文件播放器中跳到对应时间：视频显示原画面，音频显示音频进度条。播放到该句结束时自动暂停；再次点击可停止，点击其他句子会重新定位。切换历史记录或结果页签时停止当前播放。“待核对”和关键词搜索结果也支持点击句子播放，无需重新上传已有记录。

播放器保留原文件时间轴，可手动拖动进度条查看其他位置。系统按文件实际音视频轨道选择播放器，只有音轨的 MP4 会按音频处理。浏览器无法解码的文件会显示格式提示；常见 H.264/AAC MP4、MP3、WAV 可直接播放。

## 边录音边显示文字

### 波形编辑与分句调整

打开已完成的识别记录，在“完整转写”点击某句后的“调整分句”，或展开“波形与分句调整”。首次读取原音频生成振幅波形，波形沿用识别的原始时间轴，与音高图含义不同。选择分句后，绿色开始边界与粉色结束边界可拖动，也可直接输入秒数；边界获得焦点后左右方向键每次微调 0.05 秒，按 Shift 时为 0.5 秒。支持 2/4/8 倍缩放与横向滚动。点击“试听当前时间段”核对，再点“保存时间调整”。修改不会自动保存，“重置本句”放弃当前未保存的调整。

“拆分当前句子”中分别设置切分时间和前、后半句文字。可在只读原句中放置文字光标，再点“按文字光标分配前后句”；按文字比例预填的切分时间只是提示，需根据波形和原声核对。两半都需有文字，合起来必须与原句一致，不能丢字或重复；每段至少 0.05 秒。若需要改错字，先用“编辑文字”保存，再拆句。先保存或重置起止时间的变动，再执行拆分、合并。

“与时间上的下一句合并”始终取按时间排序的下一句，保留两句全部文字，时间覆盖从两句最早开始到最晚结束的整段音频（包括中间停顿）。两句说话人不同时，必须明确选择合并后的归属，也可选“未确定说话人”。保存后，转写列表、按说话人整理、原声播放、搜索、复制和导出使用新分句。发言统计改按人工调整后的分句范围估算；重叠范围按各说话人分别计时。原始模型说话人时间段与音高结果继续保留。

“撤销上一步分句调整”可恢复最近一次保存前的分句；若之后已编辑文字、修改归属或重新分析，撤销会禁用以避免覆盖后续修改。原分句保存在记录的 `originalSegments` 中，调整前后记录在 `segmentEditHistory`，最近一次撤销快照为 `segmentUndo`。波形缓存位于 `audio_llm_backend/data/waveforms/`，按原文件大小与修改时间区分版本，不更改原音视频。

拆合句后自动清除旧编号的 AI 勾选和已显示的片段总结，新的片段总结、文字编辑及归属调整均校验分句结构版本，拒绝旧窗口操作错误句子。旧文字草稿若遇到其他窗口拆合句，会保留在草稿恢复区供复制。原识别分数不再用于已调整边界的片段，页面标记“分句已调整”；全文重要信息提示重新提取。没有保存分句时间的旧记录不能直接做波形分句编辑，需先完成带时间的识别。

### 批量识别与排队

选择音频/视频时可按 Ctrl 或 Shift 多选，单次最多 20 个。点击“上传并识别”后，文件依次上传，每个成功上传的文件马上进入本机服务端队列；当前文件处理完成后，自动开始下一个。队列按上传成功的先后顺序处理，单个识别任务独占原有模型处理流程，不并行加载多份识别模型。可继续选文件并点击“添加到识别队列”，也可把新录音作为待上传文件加入队列。

“识别队列”显示当前阶段、排队位置和最近完成状态，可查看进度/结果，尚未开始的文件可以取消排队。取消保留已上传的原文件和记录，不强行中断正在推理的模型。某个文件上传失败或识别失败会显示对应提示，其他文件继续；部分完成的结果保留在历史记录中。显示全部待处理任务和最近 20 条已结束任务，完整记录仍可在历史区查找。

排队状态保存在 `audio_llm_backend/data/records/` 的记录中，关闭网页或切换历史不会停止已经上传的任务。服务重新启动后继续处理尚未开始的排队文件；重启前正在识别的文件标为处理中断，保留已有结果，不自动重做该文件。请保持本地服务运行。尚未上传的选择和失败上传的草稿只保留在当前页面中，刷新前请先上传或检查提示；上传响应丢失时先检查队列/历史，避免重复提交。队列处理期间可继续添加文件，本地实时录音与其他 AI 操作待队列结束后再使用。

接口：`POST /api/recognition` 上传后立即返回任务编号与 `Queued` 状态；`GET /api/recognition/queue` 获取队列及等待位置；`POST /api/recognition/{task_id}/cancel` 取消未开始任务；原有 status、历史、原声播放和编辑接口继续使用。

### 转写文字编辑

在“完整转写”或“待核对”中点击某句的“编辑文字”，修改后点击“保存修改”，也可使用 Ctrl + Enter 保存、Esc 取消。每条最多 20000 字，不允许保存空白文字。未保存的草稿会在当前页面内保留，切换按时间/按说话人或打开其他历史记录再返回时仍可继续编辑；关闭或刷新页面前，浏览器会对未保存修改提示确认。没有分句时间的旧记录支持编辑整段全文。

保存只修改文字，保留原始音视频、时间段、分句编号、说话人归属和音高数据；历史记录、关键词搜索、复制、TXT 导出及新的 AI 总结均使用修改后的文字。原始识别文本和每次修改前后的文字保存在该记录 JSON 中，编辑器的“填回识别原文”只填入原文，仍需点击保存才会生效。记录目录为 `audio_llm_backend/data/records/`；记录包含 `originalTranscript`、分句的 `originalText`、`transcriptEdits` 修改历史和 `transcriptRevision` 版本号。

原识别模型的词语分数不适用于人工修改后的文字，因此该句显示“已编辑”，清除旧模糊词高亮，不将手动修改视作识别准确率证明。旧的全文摘要和待办保留但标记需更新，点击“重新提取重点”成功后解除提示；原来显示的片段总结会收起，后续总结按新文字重新生成或读取对应缓存。两个窗口修改同一句时检查编辑前原文，拒绝覆盖其他窗口已保存的修改，并保留当前草稿供复制。

### 按说话人整理内容

打开一条识别记录，在“完整转写”中选择“按说话人”，同一个人的发言会集中列出，组内按时间排序，保留每句话的原始时间段、原声播放、待核对标记和逐句归属修改。选择“按时间”可恢复时间线。没有保存说话人归属的记录，先点击“区分说话人”；未确定归属的句子会单独列在最后，不猜测人物身份。

每组提供“复制发言”和“AI 总结发言”，后者只将该组的转写交给本地 Ollama，结果显示在上方 AI 总结区并沿用片段总结的本机缓存。“导出整理 TXT”可保存全部说话人的发言；分组模式底部的复制按钮也会复制分组内容。同名但 ID 不同的说话人保持分开，可能包含多位说话人的原有提示继续保留。单组超过 120 段或 6000 字时，使用逐句勾选缩小总结范围。整理展示不改写原文，修改称呼或句子归属后会同步更新分组。

### 电脑声音与麦克风同时录制

录音区的“录音来源”可选择“仅麦克风”“电脑声音＋麦克风”或“仅电脑声音”。选择包含电脑声音的模式后，点击“开始录音”，在浏览器共享弹窗里选择整个屏幕或浏览器标签页，并勾选“共享音频 / 系统音频”。混合模式还需允许麦克风权限。

声音来源是否可共享由浏览器和操作系统决定。建议在 Windows 的 Chrome 或 Edge 中使用；内置浏览器若未提供共享音频，请在上述浏览器中打开启动窗口显示的本机地址。未勾选共享音频、取消授权或麦克风不可用时，会明确提示，不会将只有一路的声音当作双路录音保存。

两路音频经 Web Audio 混成一条音轨，分别保留混音余量；不会回放到扬声器，以减少啸叫。请使用耳机避免麦克风再次收录扬声器声音。录音、音量监测和实时转写都使用同一份混合音频。浏览器要求选择屏幕作为授权来源，但本项目的录制器只接收音轨，不保存屏幕视频。停止共享会结束录音并保存已录到的部分；结束录音会释放麦克风、屏幕共享和音频处理资源。

实现依据：[屏幕音频共享接口](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)、[Web Audio 混音输出](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaStreamDestination)。浏览器可能不提供所选共享来源的音轨，因此程序会检查实际返回的音轨，不能仅凭“允许共享”就判断双路录音成功。

### AI 总结选中的转写片段

打开一条已完成的识别记录，在“完整转写”中点击某条的“AI 总结这段”，或勾选多条后点击“AI 总结选中内容”。结果显示简短摘要、最多三条重点、原文和对应时间范围，可复制或重新总结。未保存分句的旧记录可概括原来的整段转写。全文摘要与待办仍保留在“重要信息”中。

片段总结使用当前本地 Ollama 文本模型，仅发送所选转写；不重新识别音频。一次最多选择 120 段、6000 字，超过时需缩小范围。结果按来源文字和模型缓存到 `audio_llm_backend/data/fragment-summaries/`，再次总结相同内容可读取已保存的结果，重新总结会更新该缓存。此步骤不替换原始音频、转写、全文摘要或音高统计。模型繁忙、连接失败或返回无效数据时，页面会提示重试并保留原文。

录音区默认勾选“边录音边显示文字”。点击“开始录音”并允许麦克风后，下方“实时文字”约每 4 秒追加一段；声音只交给本机 Whisper，不依赖浏览器云端语音服务或 API 密钥。首次加载模型、电脑负载较高时会有额外延迟。可复制实时文字。

点击“停止录音”后，会补查剩余片段。实时文字是短片段临时预览，句子边界或个别字可能不准；点击“上传并识别”才会保存完整录音、正式转写、说话人、重点和音高结果。开始新录音会清空上一段临时预览；录音达到配置的时长上限（默认 300 秒）自动停止。取消勾选可只录音。

使用支持 AudioWorklet 的现代浏览器打开本机网址。实时预览失败时，完整录音仍可停录后上传。完整识别任务期间不另开实时录音，其他窗口占用模型时会提示等待。

录音时会出现竖向音量条：声音合适时显示绿色，过小时显示黄色，过大或接近削波时显示红色并升高。持续没有明显输入时提示“当前检测不到声音”；重新检测到声音后，提示逐渐淡出。这个条表示麦克风音量，不是说话音高；录音结束后关闭，不影响“音高统计”页的基频图。它是录音时的即时提示，无法保证转写一定准确。

## 关键词搜索

“识别结果”上方输入关键词，选择“当前记录”或“全部历史”，稍候或按回车查看“搜索结果”。支持中文繁简转换和英文大小写匹配，按普通文字搜索，不把输入作为正则表达式。

转写和“重要信息”下方还会把部分关键词、明确的日期时间，以及待办事项中填写的人名显示为圆角小标签。标签右上角的搜索图标会在浏览器新标签页搜索该词；点击转写句子的文字仍播放原声。网页搜索会把所点词语发送给搜索网站，因此只点击需要公开查询的内容。标签依据已有关键词和简单文字规则生成，不保证找出所有人物或时间。

结果显示文件名、命中句子、说话人和时间段，关键词以紫色高亮。点击小喇叭可直接复听该句，重复点击停止；“打开这条记录”可查看完整结果。没有打开记录时自动搜索全部历史。最多展示 100 条命中语句，并说明总数量；搜索不会修改原文、说话人标签或导出内容。

## 模糊片段与待核对

新上传音频在转写时自动保存逐词分数、整句分数和原声响度。识别把握较低的词语在“完整转写”中用橙色标出，相关句子显示“待核对”及原因；“待核对”页按时间单独列出这些片段，可点击小喇叭复听。TXT 导出包含待核对片段、时间和原因。

旧记录打开后，进入“待核对”页点击“检查模糊片段”。没有分数的旧记录会重新分析本地原声，再按时间匹配到已保存的分句，保留原文、时间、说话人名称、摘要和音高图。有分数时直接复用，不重复转写。

提示依据是词分数低于 0.55、整句平均对数分数低于 -0.8、可疑背景声、异常重复或片段平均响度低于 -38 dBFS 等规则；分数不是正确率。待核对不代表一定识别错误，未标记也不保证正确。缺少足够证据的片段明确显示暂无法判断，不编造替换文字。分数来源见 [faster-whisper 官方代码](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)。

## 说话人标签

新音频完成转写后，会通过本地 sherpa-onnx 模型自动区分说话人。同一组先标为“说话人 A、B……”，在“说话人称呼”中可快捷选择“男生A”“女生A”或输入自定义名称，点击“保存称呼”后，该组的文字、复制内容和 TXT 导出会统一使用这个名称。系统不根据声音猜测性别，名称由使用者设置。

已有记录打开“完整转写”，点击“区分说话人”即可补做，无需重新转写。每条文字前方的下拉框还可单独调整归属。背景音乐、声音过轻、多人同时说话及很短的片段会影响分组；可点击小喇叭核对。分组按现有转写时间段匹配，一条包含多人时会给出提示。

首次准备会下载约 47 MB 的说话人模型到 `models/speakers`，之后可在本机离线使用。模型来自 [sherpa-onnx 官方说话人分组示例](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/python.html)。

## 发言统计

识别结果中的“发言统计”页显示每位说话人的累计发言时长、占比、转写句数和字符数（不含空格、标点），并可导出 CSV。发言占比和饼状图是两个独立的可收起窗口，点击标题即可分别展开或收起。饼状图颜色与发言占比对应，只显示各组的百分比；较小的扇区把百分比标在圆外。页面下方的“历史记录”也是可收起窗口。已有说话人分组的历史记录直接显示统计；尚未分组时可在该页点击“区分说话人”。修改说话人称呼或调整某句话的归属后，重新打开统计页即可看到更新。

时长优先依据本地说话人模型保存的语音时间段，同一说话人的重叠区间只计一次；手动调整归属的句子按该句时间段重算。占比以所有说话人累计时长之和为基数，因此多人同时讲话时会分别计时。没有单独保存语音时间段的旧记录按转写句子的时间估算。统计结果依赖自动分组和转写时间的质量，可点原声核对。

## 历史记录整理

历史记录可按名称、标签或转写文字搜索，可只看收藏，并按时间或名称排序。每条记录可点击“整理”修改显示名称和标签，或点击星号收藏；同一原文件名出现多次时会提示“同名 N 条”。显示名称也用于结果播放器、搜索结果和导出标题。整理不改动原始文件、转写和识别结果；正在处理的记录需完成后再整理。

## 打开项目

双击本文件夹内的 `start.cmd`。启动器会检查 Python 环境和模型，启动本机服务后自动打开浏览器。启动窗口会显示实际网址，例如 `http://127.0.0.1:8000/`；如果端口已被其他程序占用，会在 8000–8010 中选择可用端口。启动器通过专属健康接口检查项目身份、接口版本和运行模式，避免打开其他项目的网页。

打开的网址根路径 `/` 是课程项目封面。点击“进入音频识别系统”前往 `/app`，进行真实录音、上传、转写、重点提取和历史记录操作；功能页右上角可返回封面。封面右侧的句子、摘要、音高与声波都是交互示例，不会读取真实识别记录。封面样式已经编译到本地 `cover.css`，运行时不需要 Tailwind CDN 或 Google Fonts。

若修改封面 HTML 中的 Tailwind 类名，可在 `audio_llm_backend/web` 目录运行 `npm exec --yes --package=tailwindcss@3.4.17 -- tailwindcss -i cover.tailwind.css -o cover.css --content cover.html --minify` 重新生成离线样式；正常启动项目无需 npm。

首次准备大模型环境时，双击 `install_ollama.cmd`，它会在本文件夹安装官方 Ollama 便携 CPU 程序（下载约 37 MB），并下载 Qwen2.5 3B 模型（约 1.9 GB）。下载中断后可重试。准备完成后，平时只需双击 `start.cmd`，启动器会自动启动并检查本地模型服务。

网页仅供这台电脑访问，电脑无需连接手机或局域网。模型安装完成后，本地识别和重点提取可断网使用。第一次在新电脑使用时，依赖和模型的下载需要网络。保留启动窗口即可继续使用，按 Ctrl+C 结束网页服务。

1. 在封面点击“进入音频识别系统”，然后录音或选择本地音频/视频文件。
2. 点击“上传并识别”，等待转写、重点提取和音高分析。
3. 查看完整文字、重要信息和音高曲线；在历史记录中重新打开结果。
4. 如果曾因本地模型未启动而没有重点，打开该条历史记录，点击“重新提取重点”。它直接使用已保存的文字，不必再次上传或转写；原有文字和音高图会保留。

CPU 本地识别的处理时间受录音长度影响。默认使用 Whisper small、CPU int8 和 Qwen2.5 3B，适合当前 16 GB 内存电脑；首次加载模型会额外花费时间。

## 手机通过局域网连接电脑

手机与电脑连接同一个 Wi-Fi 时，可以不用 USB 数据线：

1. 关闭已经打开的 `start.cmd` 窗口（它只允许本机访问），双击 `start_lan.cmd`。首次运行会请求管理员权限，添加只允许本地子网访问 TCP 8000–8010 的防火墙规则。
2. 启动窗口会列出可用地址，选择与手机同一 Wi-Fi 的那个（通常标有 `[WLAN]`），例如 `http://10.40.225.155:8000`。
3. 在手机应用“设置”中填入该地址，点击“保存地址”，再点击“检测连接”。

校园网或公共 Wi-Fi 常开启设备隔离，手机无法访问电脑。此时可打开电脑的“移动热点”让手机连接（地址一般为 `http://192.168.137.1:8000`），或让电脑连接手机热点。局域网模式运行期间，同一网络的其他设备也能访问本服务，用完请关闭窗口；平时使用 `start.cmd` 仅限本机访问。

## 配置与模式

配置文件为 `audio_llm_backend/.env`。默认参数：

```env
AI_MODE=local
MOCK_MODE=false
LOCAL_WHISPER_MODEL=models/whisper-small
LOCAL_WHISPER_DEVICE=cpu
LOCAL_WHISPER_COMPUTE_TYPE=int8
LOCAL_LANGUAGE=zh
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:3b
```

`models/whisper-small` 相对于项目根目录解析。启动脚本明确选择真实本地模式，因此不会因旧 `.env` 中的 `MOCK_MODE=true` 而返回演示结果。云端模式通过 `start_cloud.cmd` 启动，需在 `.env` 填写服务提供方的 API Key、地址和模型；`start_mock.cmd` 返回标记为演示的内容。

Ollama 优先使用 `tools/ollama/ollama.exe`，其次查找系统安装的 Ollama。便携安装器从固定版本官方 Windows ZIP 中提取 CPU 程序、依赖和许可证，不下载大型 CUDA 组件。程序自动在本机回环地址启动 Ollama，新启动进程的模型存放在 `models/ollama`。如果电脑已运行 Ollama，则沿用现有本机服务并检查所需模型。

## 音高图的含义

曲线纵轴是检测到的人声基频（Hz），分析范围为 65–600 Hz，横轴是录音时间；同时提供分布柱状图以及有效音高的平均值、中位数、最低值、最高值等。停顿、无声片段和无法可靠估计的部分不填作 0 Hz。音乐、多人重叠和强噪声会影响估计。

## 保存与排查

原始音频及结果保存在 `audio_llm_backend/data` 下，当前源代码和启动脚本保存在本文件夹。以前版本的源码压缩包可保存在 `backups/`，后续修改前按日期另存备份。

- 找不到 Python：安装 Python 3.11 或 3.12，再双击 `start.cmd`。
- 找不到 Ollama：双击 `install_ollama.cmd` 完成本文件夹内的便携安装，也可以安装官方桌面版 <https://ollama.com/download/windows>。
- 模型下载失败：检查网络后重试，已经下载的部分可继续复用。
- Ollama 启动失败：查看 `logs/ollama.log`。
- 识别失败：网页会显示具体错误，检查音频内容、文件格式与模型配置。

开发检查可以运行 `start.cmd --no-browser --check`，它完成环境和本地模型检查后退出；仅用 `--no-browser` 会保持服务运行。

桌面的项目 ZIP 为源代码与启动脚本备份，不包含 `.env`、用户录音、识别记录、Python 环境和模型权重。完整的本机运行文件保留在本项目文件夹，换电脑首次运行需要重新准备依赖和模型。
